# Восстановление базы из ночной копии

Сервер раз в сутки кладёт копию базы в хранилище (Cloudflare R2 / S3), папка `backups/`,
и хранит 14 последних (см. `backend/src/modules/ops/nightly-backup.ts`). Копия делается,
только если на Render заданы переменные `S3_*`.

Имя файла подсказывает формат:
- `light-crm-<дата>.sql.gz` — полный дамп pg_dump (схема + данные);
- `light-crm-<дата>.jsonl.gz` — только данные, если pg_dump на сервере не сработал.

## 1. Скачать копию
Cloudflare → R2 → бакет → `backups/` → свежий файл → Download. Или:
```
aws s3 cp s3://<S3_BUCKET>/backups/<файл> . --endpoint-url https://<account_id>.r2.cloudflarestorage.com
```

## 2. Подготовить базу
Создать новую базу на Render (или взять старую) и остановить сервис `light-crm-backend`
(Suspend), чтобы в базу никто не писал во время восстановления.

## 3а. Файл .sql.gz
```
gunzip -c light-crm-<дата>.sql.gz | psql "<External Database URL>"
```

## 3б. Файл .jsonl.gz
Из папки репозитория после `npm ci`:
```
DATABASE_URL="<External Database URL>" npm run -w backend restore:backup -- light-crm-<дата>.jsonl.gz
```
Скрипт создаёт схему (как при старте сервера), стирает строки в таблицах из копии (включая
демо-записи сида) и загружает строки из копии. Всё в одной транзакции: при ошибке база не меняется.

## 4. Вернуть в работу
Если база новая — поменять `DB_*` у сервиса на её данные. Снять Suspend, войти в CRM,
открыть пару диалогов и сделок. Вложения лежат в хранилище (`uploads/`), их восстанавливать не нужно.

## Проверка раз в месяц
Скачать свежую копию и восстановить её в отдельную пустую базу по шагам выше.
